# 健康检查与自测

> 两类检查：① 模型"满血/降智"检测；② 内核"防污染"完整性检测。

---

## 一、模型能力健康检查（降智检测）

模型可能因版本变更、高峰负载、上下文过长而"降智"。开工前必须体检，运行中保持熔断。

### 1. 开工体检（固定探针，答案已知）

| 探针 | 测什么 |
|---|---|
| 一道简单逻辑题 | 基础推理 |
| 一个该走工具的计算题 | 精确计算 / 是否正确调用工具 |
| 一个含多个约束的小指令 | 指令遵循（看是否漏掉约束） |
| 对话中前置的设定 | 上下文记忆 |
| 一次最小检索/取数 | 工具链路是否正常 |

- 全部通过 → 满血，放行；
- 任一异常 → 判定降智，**不许开工**，提示用户并尝试：重试 / 新开会话 / 换模型 / 缩短上下文 / 拆分任务。

### 2. 运行熔断

出现以下信号立即暂停、提示、重试或降级：
- 连续出错、计算异常；
- 忘记任务书、前后矛盾、重复啰嗦；
- 拒绝执行它本应能做的步骤；
- 置信度异常（该确定的含糊、该存疑的笃定）。

### 3. 显式告知

让用户看到当前模型状态、能力是否受限、取数时间。

---

## 二、内核防污染自测（完整性校验）

内核为只读，任何迭代不得直接改动。通过"指纹"比对识别污染。

### 1. 建立基线指纹

- 对纯净内核（`01_内核_只读` 全部文件）计算哈希指纹（如 SHA-256）；
- 将指纹清单存入 `04_版本归档\清源_v1.0_纯净首版`。

### 2. 每次启动自测

- 重新计算当前内核指纹，与基线比对：
  - **一致 = 未污染，放行**；
  - **不一致 = 被改动/污染，立即告警，并从 `04_版本归档` 的纯净基线恢复**。

### 3. 知识库隔离

- 新产出先进 `02_知识库\待审区`；
- 经"来源可溯 + 查验官复核"后才转入 `已审核插件（主库）`；
- 插件与内核物理隔离，任何插件膨胀都不触及内核。

---

## 三、回档

- 纯净首版标记为 **清源 v1.0**，永久保存于 `04_版本归档`；
- 任何版本异常、污染、降智无法恢复时，可整体回档至 v1.0；
- 后续迭代按 v1.1 / v2.0 编号，只增不改，均可追溯。
