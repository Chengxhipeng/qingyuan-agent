# 六阶段流程 SOP

> 元研究内核的完整流水线。每阶段三件套：标准动作 → 产出物 → 检查点（闸门）。

---

## A 开题（Define）

- **标准动作**：开场给地图 → 开题五问（决策/对象/画面/边界/红线），一次一件、三给；
- **产出物**：一页"任务书"（含假设栏）；
- **闸门**：小白确认任务书才开工。

## B 取证（Gather）

- **标准动作**：
  1. 把问题拆成子问题，指定各自要找的证据类型；
  2. 按证据金字塔**从上往下找**：荟萃/系统评价 → RCT/大型队列 → 权威数据/法规，每退一级都标注；
  3. 来源认门：学术走数据库、数据走官方/API、法规走政府；排除营销软文与无出处二手；
  4. 会变的数据（股价、汇率、政策、报价）实时调工具，标注取数时间，不靠记忆；
- **产出物**：证据登记表（主张 + 来源 + 类型 + 等级 + 时间）；
- **闸门**：关键问题不"裸奔"；证据缺口如实列出（"没有证据"本身就是结论）。

## C 核验（Verify）

- **标准动作**：
  1. 每条证据评级（A/B/C），查样本量、方法、利益冲突；
  2. 关键结论 ≥2 个**独立**来源交叉；冲突则并列、分析原因，不擅自取舍；
  3. 独立查验官复核（生成与核查分离，不共享上下文）；
  4. 主动找反证：失败/反对/证伪，回答"何时不成立"；
  5. 辨因果：关联 ≠ 因果，追问反向/第三方因素；
  6. 标注置信度（高/中/低）与争议；
- **产出物**：核验报告（含标红/否决清单）；
- **闸门**：关键结论全部复核，过不了不进下一阶段。

## D 综合（Synthesize）

- **标准动作**：
  1. 证据归类排序，搭出可追溯的"论证链"，不堆砌；
  2. 基于证据强度下明确判断、给可执行建议，带等级/置信度，不和稀泥；
  3. 分层标注"已证实 / 合理推测 / 仍有争议"；
  4. 冲突无法定论时，明说"无法定论 + 需满足什么条件"，不硬凑；
  5. 建造类任务先做 MVP（可看可点），实物迭代；
- **产出物**：结论/方案；建造类为可运行原型；
- **闸门**：结论有据、推测有标、建造有原型。

## E 交付（Deliver）

- **标准动作**：
  1. 翻译成人话：先讲结论/用法，再讲依据，术语解释；
  2. 给可看可点的实物（软件是能双击打开的成品，不是代码）；
  3. 对照任务书"成功画面"逐条演示，没做到的明说；
  4. 附一页使用说明（无作者在场也能用）；
  5. 交代边界、已知问题、注意事项；
  6. 工具在干净环境实测可运行；
- **产出物**：成品 + 使用说明 + 验收清单；
- **闸门**：rubric 全过 + 萌新跟做测试通过（真萌新独立从 0 跑到第一次成功）。

## F 复盘（Learn）

- **标准动作**：
  1. 产出与任务书逐条对照，复盘判断对错，诚实不护短；
  2. 提取可复用资产（检索策略、来源、框架、提示词），经审核后归档；
  3. 把领域地图/术语/标准/红线/坑反哺进对应行业插件；
  4. 记录遗留问题、新问题与下一步；
  5. 元学习：复盘六阶段流程本身并迭代；
- **产出物**：复盘记录 + 新增/更新的资产与插件 + 遗留清单；
- **闸门**：资产真入库、插件真更新、遗留真记录。

---

## 飞轮

F 沉淀的资产与插件回流到下一次 A，使起点逐次抬高；方法论本身也在每轮被自己检验和改进。
